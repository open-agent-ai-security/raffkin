The Raffkin guardrail bridge exabeam-mcp-bridge.py

Your log data is untrusted input — an attacker can plant a payload in an alert knowing an agent will read it. So Raffkin never talks to Exabeam directly. Your agent talks to a local bridge MCP that proxies every call to the real Exabeam MCP — and because it sits in the path of every call, it's the one place to hook input and output for safety.

Writes fail closed
Refusing a write is safe — the finding isn't lost, just not persisted with a live payload. So a neutralizer error stops the write rather than storing raw content.
Reads fail closed
Unscreened platform text never reaches the model. A block the screen cannot process is withheld and the gap is named; the rest of the result stands and the fault is logged.
Narrow by design
Only free-text write fields are defanged; IDs, enums & state are left exact so a formula-shaped identifier can't corrupt a write. "Do no harm; stop the obvious."
