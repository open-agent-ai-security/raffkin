Executive Summary
Agent Remit (as declared) · Remit v1.9
Raffkin is an agentic SOC skill suite — soc-investigate, triage-cases and rule-tuning — that works a single Exabeam New-Scale tenant through the Exabeam MCP to investigate alerts and cases at depth, prioritize the open case queue read-only, and propose (never apply) detection tuning. It may read freely and escalate by opening cases and writing notes, but dismissing an alert, closing a case and sending platform email require a host-enforced human gate on both Claude Code and Codex. Containment, rule writes, shell execution and unconfigured third-party enrichment are forbidden outright, and every write must be deterministically neutralized and audited without the audit trail holding free text.
Behavior Summary (as observed)
Raffkin's controls are real and live in code: a bundled hook that fails closed, a bridge that screens every read, neutralizes every classified write and refuses a close by another route, and an audit trail that is on by default — and no chain reaches a consequential action without a human in it. The residual pattern is enumeration where the remit asks for closure: the deny tier is a list of exact names that omits two remit-named containment classes and cannot deny a future rule-modifying tool; the write neutralizer defangs only an allowlist of field names; and the sweep's no-write rule rests on instruction for the two escalation writes, with no budget at all on Codex. Each gap fails toward a human prompt rather than an open door, but each is a place where the deterministic control the remit promises becomes a judgment call — and the audit trail cannot yet show whether a case was closed as a false positive.
Scope of Analysis
A Claude Code / Codex plugin whose three skills are prompt files (plugin/skills/*/SKILL.md) driving a bundled stdio MCP bridge, exabeam-mcp-bridge.py, which mints OAuth client-credential tokens from ~/.exabeam-mcp.env and proxies every call to the remote Exabeam MCP over https. The bridge screens every read block and tool definition with canonicalize.py, neutralizes write arguments with neutralize_output.py, forwards only state fields on updates, refuses a closing create_case, and writes a structured audit trail through observra_logging.py. On Claude Code a bundled PreToolUse hook (hooks/gate.py) reads the tier file permissions.json to allow, ask or deny by bare tool name with an escalation-write budget; on Codex the generated .mcp.codex.json supplies per-tool approval modes and disabled_tools.

Maturity Scoring Rubric

Every score above is based on this scale. A score is a snapshot of observable posture — not a verdict on the people or team behind the system.

Score Label Meaning
5 Exemplary Best-in-class; automated, continuously tested, reference quality. Rarely achieved in shipping systems.
4 Strong Comprehensive controls, active management, minor gaps. Production-ready.
3 Established Documented controls consistently applied; known gaps accepted. A respectable baseline.
2 Partial Some controls exist but coverage is incomplete; key gaps remain.
1 Ad hoc Informal or inconsistent measures; relies on individual judgment.
0 Absent No evidence this category is addressed at all.
Weighting: the weighted overall above is the sum of each category's score × weight (the per-category weights are shown on each card). Zero Trust carries double weight by design; see the RAISE framework reference for the rationale.
