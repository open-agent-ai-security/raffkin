Summary
The Agent (as modeled)

socxen is three AI skills (investigate one alert or case, triage the open case queue, propose detection-rule tuning) that run inside Claude Code or Codex and work an Exabeam New-Scale tenant through a small local bridge. The analyst at the terminal is the only trusted voice. Everything it reads from the tenant (alert names, event records, case notes, rule descriptions) is attacker-influenceable, and so are the tool definitions the remote service publishes. It can open cases and write case notes freely. Dismissing, closing and sending platform mail sit behind a host-enforced human prompt, and containment and rule changes are blocked outright. Two trust surfaces matter most: the host gate between the model's decisions and the bridge, and the bridge's read screen and write neutralizer between the tenant and the model.

Priority Threats (led by attack paths)

Fix these first. Text planted in cases can steer a queue sweep, which is supposed to be read-only, into writing to the tenant. On Claude Code the gate lets the first two case or note writes of any session through without a prompt. On Codex, socxen's own map sets both write tools to auto-approve; Codex still prompts today, but only because Exabeam's own tool annotation marks those tools destructive, so that protection depends on Exabeam rather than on socxen. The durable fix is a read-only tool allowlist for sweeps, enforced in the bridge that both hosts share. Second, the write-side redactor misses common OpenAI-style and GitLab key formats. A key that shows up in telemetry can therefore land verbatim in a case note visible across the tenant, or in approved mail. Adding those prefix patterns closes it.

Smaller gaps: the single-case skill never tells the analyst when telemetry tried to give it orders. The record of which tool definitions the service published is lost when the startup fetch fails. The gate log stores raw mail recipients, and neither log records why a case was closed. A future platform write tool whose text sits under an unfamiliar field name would skip neutralization. What holds up well: the dismiss/close/mail gate fails closed and holds headless, the bridge refuses a close routed through case creation and never overwrites analyst text, dependencies are hash-locked, and credentials only travel over https to the configured tenant.
