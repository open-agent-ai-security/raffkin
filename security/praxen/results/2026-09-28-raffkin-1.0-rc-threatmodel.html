Summary
The Agent (as modeled)

Raffkin is a set of three SOC skills (investigate one alert or case, sweep the open queue, propose rule tuning) that run inside Claude Code or Codex and reach a single Exabeam tenant only through a bundled local MCP bridge holding the operator's API key. Its untrusted input is tenant telemetry - alerts, events and case notes written by whoever generated the activity - plus any payload the analyst pastes in. The consequential things it can do are write to the tenant (open cases, add notes, and, only behind a human prompt, dismiss, close or send mail). Code-level controls sit at two points: a host hook that asks or denies before tool calls, and the bridge, which screens what comes in and neutralizes what goes out.

Priority Threats (led by attack paths)

Two attack chains deserve attention first. In the first, text planted in a case note can talk a queue sweep into opening cases or writing notes on the tenant with no prompt at all. The sweep's no-write rule exists only in the prompt; Codex allows these two writes without limit, and Claude Code allows two per session. The fix is a sweep-mode allowlist enforced in the bridge, plus giving Codex the same write budget. In the second, a formula or live link copied from telemetry into any write field outside the bridge's short list of neutralized field names lands in the platform record as live content. A human still approves such a tool, but the fix is to neutralize every string on writes the bridge does not recognize.

Behind those two: the containment and rule-write deny list is a list of exact names, so a password-reset, quarantine or future rule-modifying tool is only prompted, never denied. The audit trail cannot show that a case was closed as a false positive, and it drops guardrail counts on failed calls. Tool-definition changes are visible only after the fact. The credential file is used even when it is readable by other users. Resistance to visible, plain-language injection still depends on the model following its instructions. The dismiss/close gate itself, the credential transport, the dependency pinning and the read-side screen are solid.
